# 统一账号权限

管理员在 `/access/admin.html` 管理邮箱名单。名单存在 Supabase 的私有 `app_private.staff_access` 表中，网页代码不包含完整名单。

| 角色 | 使用范围 | 管理名单 |
| --- | --- | --- |
| admin | 全部系统 | 可以 |
| analyst | 全部系统 | 不可以 |
| staff | Skill 市集、OKR 排期、两个训练营排期 | 不可以 |

按产品要求保留注册后直接登录，Supabase 的 `mailer_autoconfirm` 为 true。注册接口通过 `auth.users` 触发器检查名单，拒绝未授权邮箱；禁止账号自行改邮箱。邮箱字符串通过名单检查不代表已验证邮箱归属。

数据库权限每次按当前账号和名单计算，不信任用户可修改的个人资料或浏览器角色。停用账号会同时撤销刷新令牌、结束会话并设置禁止登录；已发出的令牌也会立即失去业务数据权限。历史业务记录保留。

`setup.sql` 在各系统初始建表脚本之后执行。现有系统如重跑旧版初始化脚本，必须最后重跑本脚本，以免恢复旧成员权限。初始名单单独录入，不能提交到公开仓库。

旧的运营分析、话术复盘成员入口统一跳转到管理员页面。旧成员表不再控制访问，客户端也没有写入权限。两类训练营排期已经与运营分析成员权限分开。

GitHub Pages 继续托管公开的页面代码，业务数据由 Supabase 权限保护。页面访问检查负责登录跳转和隐藏无权使用的入口，不能代替数据库授权。

运行测试前在 `camp-schedule` 执行 `npm ci`，然后在仓库根目录运行 `NODE_PATH=camp-schedule/node_modules node --test access/tests/*.test.js`。
