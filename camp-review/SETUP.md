# 训练营周复盘 · 上线步骤（约 5 分钟）

页面代码 push 到 GitHub 后会自动部署到
`https://internal.aurange.cn/camp-review/`。

数据库直接复用 Skill 市集的 Supabase 项目：`config.js` 里已经填好和
`skill-hub/config.js` 相同的项目地址和 Publishable key，账号也和 Skill 市集共用
（邮箱验证在 Skill 市集上线时已经关掉，这里不用再设置）。只需要建表、开通成员两步。

## 第 1 步：建表

1. 打开 https://supabase.com ，进入 Skill 市集用的那个项目
   （项目地址和 `skill-hub/config.js` 里的 `SUPABASE_URL` 一致）
2. 左侧菜单 **SQL Editor** → **New query**
3. 打开本目录的 `setup.sql`，全选复制，粘贴进去，点 **Run**
4. 看到 `Success. No rows returned` 就成功了

> 脚本可以重复执行，以后有更新也是整段重跑。
> 如果提示「没找到 public.profiles 表」，说明打开的项目不对，换成 Skill 市集那个项目再执行。

## 第 2 步：开通第一批成员

Skill 市集是开放注册的，所以复盘数据多加了一层「成员白名单」：只有名单里的邮箱
登录后才能看到和修改数据。

1. 先让第一批同事（包括你自己）注册账号。已经有 Skill 市集账号的不用再注册；
   没有的可以在 Skill 市集或复盘系统的登录页点「注册」
2. 在 SQL Editor 里执行（把邮箱换成真实的，可以一次写多行）：

   ```sql
   insert into public.camp_review_members (email) values
     ('你的邮箱'),
     ('同事的邮箱');
   ```

3. 如果报错「还没有注册账号」，让对方先注册，再执行一次

之后加人就不用进后台了：任何成员都可以在页面右上角「成员」页添加或移除同事。

## 第 3 步：发布

```bash
git add camp-review && git commit -m 'feat: 训练营周复盘系统' && git push
```

几分钟后访问 `https://internal.aurange.cn/camp-review/`，用 Skill 市集的账号登录即可。

- `camp-review/tests/` 已被 `.gitignore` 排除（里面是真实样例数据和开发规格），不会提交
- 想先试用：打开 `https://internal.aurange.cn/camp-review/?demo=1` 进入演示模式，
  数据只存在当前浏览器，不会写进数据库

## 保活

Supabase 免费版连续 7 天没有访问会休眠。仓库里的
`.github/workflows/skillhub-keepalive.yml` 每天访问一次这个 Supabase 项目。
休眠按项目计算，复盘系统和 Skill 市集共用同一个项目，所以已经被覆盖，不需要另加 Action。
万一还是休眠了（页面提示「数据库暂时连不上」），到 supabase.com 后台打开项目，
点 **Restore project** 恢复，数据不会丢。

## 安全设计

- 网页里的 Publishable key 本来就是公开的，数据安全靠数据库的行级权限保证
- 只有白名单成员能读写期次、修改记录和成员名单；非成员登录后什么都看不到，
  也没法把自己加进白名单
- 只能添加已经注册过的邮箱，避免提前放进名单的邮箱被别人抢先注册；
  账号改邮箱或被删除时，白名单会自动同步
- 成员不能把自己移出名单，所以名单里至少会留一个人
- 创建人、最后修改人、版本号、时间都由数据库填写，网页端改不了；
  两个人同时改同一期，后保存的人会收到冲突提示，不会悄悄覆盖
- 每次新建、修改、删除都会在 `camp_cohort_history` 留一份整行快照

## 日常维护

**找回被删除的期次**（在 SQL Editor 执行）：

```sql
-- 1. 看看删过哪些期次
select cohort_id, snapshot->>'name' as 期次, snapshot->>'live_date' as 直播日期, changed_at as 删除时间
from public.camp_cohort_history
where action = 'delete'
order by changed_at desc;

-- 2. 恢复其中一期（把 123 换成上面查到的 cohort_id；恢复后会是一个新编号）
insert into public.camp_cohorts (channel, name, live_date, closed, summary, data)
select snapshot->>'channel', snapshot->>'name', (snapshot->>'live_date')::date,
       (snapshot->>'closed')::boolean, snapshot->>'summary', snapshot->'data'
from public.camp_cohort_history
where cohort_id = 123 and action = 'delete'
order by id desc
limit 1;
```

- 看完整修改记录：Supabase 后台 → **Table Editor** → `camp_cohort_history`
- 同事离职：在「成员」页移除即可；或在 SQL Editor 执行
  `delete from public.camp_review_members where email = '对方的邮箱';`

## 给运营同学的使用说明（可直接转发）

> 📍 地址：https://internal.aurange.cn/camp-review/
>
> **第一次用**
> 和 Skill 市集共用账号，注册过的直接登录；没有账号就在登录页点「注册」。
> 登录后如果提示「还没开通」，找已经开通的同事在右上角「成员」页加上你的邮箱，刷新页面就能用了。
>
> **每周录入（每场直播后）**
> 1. 点顶部「录入数据」，选渠道：小鹅通 / B站，再选择「本期直播日期」
> 2. 打开运营统计表，把这一期的邀约、社群数据、整体转化三块连同列名复制，粘贴进大文本框。
>    不需要添加「小鹅通0301」之类的期次标题，系统会按所选渠道和日期生成名称
> 3. 点「识别数据」，看每一期卡片顶部的黄色提示（日期是推断的、总计对不上、有没识别的行等），
>    有不对的地方直接在下面的表格里改
> 4. 点「全部保存」。这期之前录过的话，默认「更新已有的这期」，已经写好的复盘结论会保留
>
> 一次粘贴多期时，将「本期直播日期」留空，系统会根据表内日期和重复出现的表格识别各期。
> 如果已经选了日期却粘贴了多期，页面会保留粘贴内容，提示只粘贴一期或清空日期后再识别。
> 选择的直播日期优先；与表内日期不一致时会提示核对，表格里每天的实际日期仍保留。
>
> B站这边：直播观看人数和直播成交从 B站后台下载的数据里看，社群人数直接填进「社群数据」表；
> 成交表的列是 直播成交(全款) / 直接付款(1v1) / 退款 / 老学员。
>
> **邀约时间怎么填**
> - 「邀约入群」表支持单日（如 `8.19`）和日期范围（如 `8.19-23`、跨月的 `8.28-9.3`），复制原表或手动填写都可以
> - 一行填写这段时间内该渠道的触达、进群总人数，系统保留日期范围，不拆成每天，也不重复累计；看板会显示「8月19日–8月23日」
> - 原来按单日记录的数据仍可照常使用；直播日期、「社群数据」和「每日成交」表继续按单日填写
>
> **数据有变化时（尾款陆续进来、补录、改错）**
> - 「全部期次」里找到那一期点「编辑」，直接改表格里的数字，或者在「每日成交」表新增一行填当天的数，然后保存
> - 也可以在编辑页用「重新粘贴覆盖表格」，把最新的整块表格再贴一次（期次名称、复盘结论、是否收完都会保留）
> - 尾款都收完了，勾上「这期已经收完了」
> - 两个人同时改同一期，后保存的人会收到提示，可以选重新加载，或者用自己的版本覆盖
> - 改错了也不怕：编辑页的「修改记录」里可以载入之前任何一个版本，再点保存
>
> **四个核心指标的口径**
> - 邀约入群率 = 进群人数 ÷ 触达人数（朋友圈这类没有触达数的渠道不计入）
> - 直播到课率 = 直播出勤人数 ÷ 直播当天社群人数
> - 直播转化率 = 直播中付了定金、之后补齐尾款的人数 ÷ 直播出勤人数（B站：直播全款成交 ÷ 直播观看人数）
> - 社群转化率 = 总成交 ÷ 直播当天社群人数（总成交 = 直播成交 + 1v1 追单成交 + 老学员）
> - 表格里的「直接付款」指 1v1 追单成交
> - 社群数据里直播当天那一行一定要填出勤人数，系统靠它算直播到课率
>
> **周会投屏**
> 看板顶部有每次复盘的流程指引：会前运营粘贴并核对数据，填好复盘结论、本期经验、上期行动效果及下期行动；会上先过数据、看最近八期趋势，再讨论复盘并确认行动；会后保存共识、落实负责人和完成时间，下期回来验证效果。「查看八期趋势」可直接跳到走势图。
>
> 1. 打开「复盘看板」，用顶部「‹ 上一周 / 下一周 ›」切到要复盘的那一周，可以按渠道筛选
> 2. 点「投屏模式」进入全屏大字版，导航和编辑按钮会隐藏，按 Esc 退出
> 3. 每一期从上往下看：直播 / 一对一 / 总转化人数 → 4 个核心指标 → 转化漏斗与数据洞察 → 复盘与行动
> 4. 点「编辑本期复盘」，回顾上期行动效果，记录经验，再制定下期行动；原有「编辑结论」也会进入同一份复盘
> 5. 页面下方「最近 8 期走势」展示截至所选周、每个渠道最近 8 期的变化：3 项人数（直播转化、一对一转化、总转化）和 4 项率（邀约入群率、直播到课率、直播转化率、社群转化率）
>
> 人数缺项时图中留空，数据表显示「—」；明确填写的 `0` 会保留，不会当成缺失。同一天的多期各自展示，日期后的括号用来区分记录，不会合并人数。图上当前周的数据点会放大，也可以展开「看数据表」逐期核对。尚未收口的期次会在提示和表格中标明，尾款、退款更新后趋势仍可能变化。
>
> **查找历史经验**
> 点顶部「经验沉淀」，可以查看所有期次已保存的经验，按直播日期从新到旧排列。选择渠道，或输入关键词查找经验内容、期次名称和日期。每条经验都标明来源，点「查看本期复盘」会回到对应渠道、对应周，并定位到那一期的复盘，便于对照原始数据与行动结果。

## 持续复盘怎么用

1. **先看成交人数。** 看板顶部展示直播转化、一对一转化、总转化人数及上期对比。小鹅通直播转化按补齐尾款计，B站按直播全款计；总转化包含老学员，B站还会扣退款。尚未填完整的表格显示已录入合计并提示缺项，不用空白冒充零；确实没有发生的项目请填 `0`。
2. **把洞察当作讨论线索。** 系统按同渠道历史数据拆解出勤规模和转化效率对成交差额的贡献，并提示成熟期基线下的情景空间、追单结构、待补尾款等。情景人数不是预测，指标上涨也不等于行动带来了上涨；未收口、缺数和小样本会有相应提醒。当前使用本地规则分析，无需配置 AI 接口。
3. **先评估上期行动。** 同渠道最近一个更早期次的行动会自动出现在「上期行动，本期效果」。填写已执行 / 部分执行 / 未执行，再记录执行证据、影响因素，选择继续采用、调整、停止或继续观察。行动目标会与上期基线和本期数据并排显示。可以先保存待复盘状态；作出后续决定时必须写明依据。
4. **沉淀可复用经验。** 在「本期经验沉淀」记录做法和适用条件，看板也可以展开查看同渠道最近三期已有的经验。想检索更早的记录，可用顶部「经验沉淀」查看全部已保存经验，再按渠道和关键词筛选。
5. **制定下期行动。** 填具体动作、观察指标和目标值；目标统一为达到或超过，百分比填 `60` 就是 `60%`。可补负责人和验证思路，也可从上期行动点「沿用到下期行动」，再调整目标。下一期录入后会自动承接。

保存前切换期次、渠道或另一份复盘时会提醒未保存内容。保存失败会保留当前输入。多人同时修改时会提示冲突，复盘覆盖只修改复盘内容，并保留最新表格；没有改动的原结论也会保留。

## 复盘数据与兼容性

- 结论仍存在原 `summary` 字段；经验、下期行动和上期行动效果存在 `data.review`，沿用现有 JSONB 数据列、权限、版本检查及历史快照，**此次更新不需要执行 SQL**。
- `review.actions` 包含稳定行动 ID、内容、假设、负责人、指标与目标；百分比目标保存为比例，例如 `0.6`。
- `review.followup` 在本期首次保存复盘时固定来源期次、行动内容和基线。上期之后改名、调整行动或删除，都不会改写这份已保存快照。本期数据仍实时更新；历史版本保留当时完整的数据和复盘。
- “上期”指同渠道直播日期严格早于本期的最近一期，同一天的多条记录不互相承接。已保存的来源不会因为后续补录期次而自动改变。
- 再次粘贴更新已有期次，以及编辑页重新粘贴表格，都会保留经验和行动。主动载入历史版本会连同该版本的复盘一起恢复；旧版本没有复盘字段时按空记录处理。
- 旧期次照常显示原有复盘结论，可逐步补充结构化经验和行动，无需批量迁移。
