# 销售话术复盘 · 上线步骤

页面 push 到 GitHub 后会自动部署到 `https://internal.aurange.cn/sales-script/`。
数据存在 skill-hub 用的那个 Supabase 项目里，账号也和 Skill 市集共用。
首次上线按第 1 至第 6 步操作，建表时同时执行基础脚本和知识库脚本。
已有系统启用训练营知识库，按下方“启用训练营知识库”执行增量 SQL，再发布前端或刷新本地页面；不需要新增 AI Key 或修改 `sales-ai` 云端函数。
已有系统启用话术原文直出和助手流式输出，按下方“升级话术助手”更新云端函数与前端；无需执行新的 SQL，也不用更换模型或密钥。
如果只是调整 AI 模型，查看第 4 节的模型设置与函数部署说明。文档中的操作步骤需要在对应环境执行，保存本地代码不会自动更新云端数据库或函数。

> 想先看看效果，可以打开 `https://internal.aurange.cn/sales-script/?demo=1`（本地预览就在网址后面加 `?demo=1`），
> 点顶部的「填入示例数据」。演示模式的数据只存在你自己的浏览器里，AI 用的是本地模拟结果。

## 第 1 步 建表

1. 打开 supabase.com → 进入 skill-hub 的那个项目
2. 左侧 **SQL Editor** → **New query**
3. 把本目录的 `setup.sql` 全部复制进去 → **Run**，看到 `Success` 就行（重复执行也没关系）
4. 新建另一条查询，复制 `knowledge-setup.sql` 的全部内容并点击 **Run**，为训练营知识库增加表和检索函数。先执行 `setup.sql`，再执行这个脚本。

## 第 2 步 把自己加进成员名单

skill-hub 开放注册，所以这个系统另外加了一层白名单。

1. 先用你的邮箱登录过 Skill 市集或本系统（没注册就先注册一个）
2. SQL Editor 里执行下面的 SQL，把邮箱换成你的
   ```sql
   insert into public.sales_members (email, user_id)
   select lower(email), id from auth.users where lower(email) = lower('你的邮箱');
   ```
   显示 `1 row` 就成功了；`0 rows` 说明这个邮箱还没注册
3. 之后其他同事在页面右上角「成员」里添加就行，不用再进 Supabase。
   名单绑定的是账号本身，所以**对方要先注册，才能被加进来**（这样别人没法抢先用同事的邮箱注册来冒用权限）

## 第 3 步 准备 OpenAI 和 DeepSeek 的 API Key

需要 AI 生成时，系统优先调用 OpenAI，页面显示为 ChatGPT；主服务调用失败时，再尝试 DeepSeek。
话术拆分、助手生成、案例分析和截图识别都使用这套切换规则。助手明确匹配到已有话术时，直接展示原文，不调用模型。

1. 打开 [OpenAI API Keys](https://platform.openai.com/api-keys)，登录后创建 API Key，保存好完整密钥。
2. 在 OpenAI 平台确认项目拥有所选模型的调用权限，并已配置 API 账单或可用额度。
3. 打开 [DeepSeek 开放平台](https://platform.deepseek.com)，登录后进入 **API keys**，创建另一把密钥，并检查 API 余额。

两家的密钥分别保存，不要粘贴到 `config.js`、网页源代码或聊天消息里。
项目通过 Supabase 函数使用这些密钥，函数会检查登录状态和系统成员资格。
OpenAI 的密钥创建流程见 [官方接入说明](https://developers.openai.com/api/docs/quickstart)。

## 第 4 步 保存密钥，部署 AI 函数

已经部署过旧版 `sales-ai` 的项目也需要执行这一步。只增加密钥，旧函数不会自动获得双服务切换能力。

### 4.1 在 Supabase 保存两把密钥

1. 打开 [当前 Supabase 项目](https://supabase.com/dashboard/project/hxlsquvryfiixvjpuxfr)。确认地址中包含 `hxlsquvryfiixvjpuxfr`。
2. 点击左侧 **Edge Functions**，进入 **Secrets**。
3. 在新增区域填写下面两项。Key 保留大写和下划线，Value 只填完整密钥，不加引号或 `Bearer`。

| Key | Value | 用途 |
| --- | --- | --- |
| `OPENAI_API_KEY` | OpenAI 平台创建的 API Key | 主服务 |
| `DEEPSEEK_API_KEY` | DeepSeek 平台创建的 API Key | 主服务失败后的保底服务 |

4. 点击 **Save**。保存后确认列表里能看到这两个名称。

默认模型已经写在函数代码里。需要调整时，可以额外添加下面的设置。

| 可选 Key | 默认值 | 用途 |
| --- | --- | --- |
| `OPENAI_MODEL` | `gpt-6-luna` | OpenAI 文字任务 |
| `OPENAI_VISION_MODEL` | 与 `OPENAI_MODEL` 相同 | OpenAI 截图识别 |
| `DEEPSEEK_MODEL` | `deepseek-flash` | DeepSeek 文字任务 |
| `DEEPSEEK_VISION_MODEL` | 与 `DEEPSEEK_MODEL` 相同 | DeepSeek 截图识别 |

更换模型时，确认账号能调用它，截图模型还需支持图片输入。模型设置只需填写 API 模型 ID。
默认使用 GPT-6 Luna，文字与截图使用同一模型，兼顾日常话术任务的响应速度与费用。
函数为 `gpt-6-luna` 显式设置 `reasoning_effort: "none"`，延续原来 GPT-5.4 mini 的非思考模式，避免升级后自动采用更高的推理强度。
支持的输入类型与参数见 [GPT-6 Luna 模型说明](https://developers.openai.com/api/docs/models/gpt-6-luna)和 [GPT-6 迁移说明](https://developers.openai.com/api/docs/guides/latest-model)。

DeepSeek 保留 `deepseek-flash`。截至 2026 年 10 月 16 日，官方将这个名称映射到 DeepSeek-V4.1-Flash，支持图片输入；
`deepseek-v4-pro` 对应 DeepSeek-V4-Pro-0813，不支持图片，因此本项目的文字与截图保底继续统一使用 Flash。
版本映射与能力见 [DeepSeek 官方模型说明](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。

升级前，在 **Edge Functions → Secrets** 检查是否已保存 `OPENAI_MODEL` 或 `OPENAI_VISION_MODEL`。
已有值会覆盖代码默认值。若仍是旧型号，将它们改成 `gpt-6-luna`；确认没有其他函数依赖这些设置时，也可以删除这两项，采用代码默认值。
使用旧 `LLM_API_KEY` 兼容配置时，`LLM_MODEL` 和 `LLM_VISION_MODEL` 也可能覆盖默认值。
这几项可能被其他函数共用，推荐为本项目配置 `OPENAI_API_KEY`，并明确填写 `OPENAI_MODEL`、`OPENAI_VISION_MODEL`，避免改动共用设置。

如果以前配置过 `LLM_API_KEY`，先保留原设置，其他共用函数可能还在使用。
新版函数兼容指向 OpenAI 或 DeepSeek 官方地址的旧 `LLM_BASE_URL` 与 `LLM_API_KEY` 配置；
本项目推荐使用上表的两把独立密钥，避免一把旧密钥被误用于另一家服务。

只更换密钥时，保存 Secrets 即可，不必重新部署函数；更新函数代码或代码中的默认模型时，继续执行第 4.2 节。
[Supabase Secrets 官方说明](https://supabase.com/docs/guides/functions/secrets)介绍了保存方式与生效规则。

### 4.2 替换函数代码

1. 回到 **Edge Functions** 的函数列表。
2. 如果已有 `sales-ai`，点击它，进入代码编辑页。如果没有，点击 **Deploy a new function → Via Editor**，函数名填 `sales-ai`。
3. 打开本目录的 `edge-function/sales-ai.ts`，选中并复制全部代码。
4. 点击 Supabase 在线编辑器的代码区域，全选原来的代码，再粘贴完整的新代码。不要把代码粘贴到 SQL Editor。
5. 编辑器里的文件名可以保留 `index.ts`；函数名必须是 `sales-ai`，与 `config.js` 中的 `AI_FUNCTION` 一致。
6. 点击 **Deploy function**。更新已有函数时，按钮可能显示 **Deploy updates**。等待后台显示部署成功。

部署地址应为 `https://hxlsquvryfiixvjpuxfr.supabase.co/functions/v1/sales-ai`。
创建和更新的操作见 [Supabase 在线部署说明](https://supabase.com/docs/guides/functions/quickstart-dashboard)。

### 4.3 检查函数验证设置

1. 打开 `sales-ai` 的设置区域，找到 **Verify JWT with legacy secret**。
2. 将这个开关设为关闭，页面有 **Save changes** 时点击保存。
3. 每次更新代码后检查一次，确认设置符合本项目要求。

函数内部仍会检查用户登录状态和成员名单。这里只调整 `sales-ai` 的验证设置，无需修改整个项目的登录配置。

## 第 5 步 发布前端

首次启用双服务时，页面和 Supabase 函数都需要更新。第 4 步部署函数后，还需要发布本目录的前端文件，才能显示服务状态。
如果只修改函数中的默认模型，重新部署函数并核对模型设置即可，页面会根据返回结果显示实际模型。知识库和话术显示等页面功能更新，需要发布前端。

在仓库根目录检查改动，再提交需要发布的文件。

```bash
git diff -- sales-script .gitignore
git add sales-script .gitignore
git commit -m 'feat: update sales script workspace'
git push
```

网站部署完成后打开 [销售话术复盘系统](https://internal.aurange.cn/sales-script/)，刷新页面并登录。
如果是在本地打开 `index.html`，保存文件后刷新即可看到前端改动。初次使用 AI 仍须完成第 4 步，知识库则需要先执行 `knowledge-setup.sql`。

## 第 6 步 检查连接，再验证一次导入

1. 登录后，页面会自动检查一次连接。在全局导航下方的 AI 服务状态区域，点击 **检查连接** 可以重新检查。等待两家服务的结果和检查时间出现。
2. 确认 OpenAI 与 DeepSeek 都已配置。OpenAI 可用时，下一次 AI 任务优先使用 ChatGPT。
3. 进入 **话术库 → 导入话术文档**，先粘贴一小段真实话术，点击 **AI 拆分**。
4. 成功后检查页面显示的实际服务提供方，以及拆出的条目。核对、修改后点击 **导入选中的 N 条**。
5. 回到话术库，确认刚导入的条目已经出现。需要识别截图的团队，再用一张可用于测试的截图验证一次。

第一次使用系统时，再到 **话术库 → 给 AI 的指引**，填写统一要求和不能说的话。课程详情、销转直播内容与 FAQ 可以按下文存入知识库。
导入的话术、指引和知识资料存在数据库里，不会写入代码仓库。

### 页面状态代表什么

页面会显示最近一次实际使用的服务，例如“最近使用 ChatGPT（OpenAI） · gpt-6-luna”或“最近使用 DeepSeek · deepseek-flash”。
每家服务会显示“连接检查通过”或“最近调用成功”等状态，并附更新时间。还没有执行 AI 任务时，不会把默认服务当成已经调用过的结果。
如果页面提示需要重新部署函数，按第 4 步更新 `sales-ai`，旧函数尚未返回页面所需的服务状态。

连接检查由 Supabase 函数访问两家的模型列表接口，不生成内容。
它可以检查后台到服务商的连接和密钥认证；余额、具体模型权限与生成任务能否成功，还要以实际调用为准。
OpenAI 接口的用途见 [模型列表说明](https://developers.openai.com/api/reference/resources/models/methods/list)。

检查结果反映的是 **Supabase 后台到 OpenAI API 的连接**。用户电脑能否打开 ChatGPT 网页，属于另一条连接，页面不会据此作判断。
如果用户当前网络连 Supabase 都访问不了，AI 请求无法到达后台，ChatGPT 和 DeepSeek 都无法通过这个系统调用。

### 什么情况下会自动切换

每次 AI 任务先尝试 OpenAI。网络错误、超时、密钥或额度问题、限流、服务端故障，以及无法解析的 JSON 等问题，会触发 DeepSeek 保底。
明显的非法请求和模型内容拒绝会直接报错，不通过更换服务商重试。
默认等待上限为 OpenAI 45 秒、DeepSeek 90 秒，发生超时切换时需要多等一会儿。
下一次新任务仍会先尝试 OpenAI，恢复后即可继续使用 ChatGPT。

两家都失败时，页面会保留错误提示。根据提示处理密钥、额度或连接问题后，再执行连接检查和实际任务。
仅看到连接检查成功，不能代替一次真实的文字或截图任务验证。

## 升级话术助手

话术助手会先在已加载、启用的话术中查找明确匹配。找到后直接返回库内原文，保留原来的换行和版本，跳过模型调用与知识库检索。
例如，库里有“零基础怕学不会”，客户问“没有编程基础，担心学不会”，明确匹配时就展示这条话术原文。
匹配不够明确时，继续检索相关知识并调用 AI。需要根据当前聊天调整已匹配的话术时，点击 **结合当前聊天调整**，即可主动进入 AI 生成。

1. 按第 4.2 节，将 `edge-function/sales-ai.ts` 的完整代码替换到 Supabase 的 `sales-ai`，点击部署，并按第 4.3 节核对验证设置。
2. 发布更新后的前端文件，再刷新页面；本地打开 `index.html` 时直接刷新。已有模型、密钥和数据库设置可以保留，无需执行新的 SQL。
3. 用话术库中已有的客户问题测试，检查结果是否显示库内原文、原换行与对应版本。
4. 点击 **结合当前聊天调整**，或输入没有明确匹配的问题，检查回复是否随生成逐步出现，并在完成后出现复制和反馈操作。

生成过程中展示的是未完成草稿，可以取消；完整结果返回并校验通过后，才提供复制和反馈操作，系统也只保存完整结果。
如果 ChatGPT 调用失败并切换到 DeepSeek，页面会先清空前一个模型的草稿，再展示 DeepSeek 的内容。取消或失败留下的片段不会保存为完整回复。

旧版云端函数返回完整 JSON 时，助手仍能展示结果，但会提示更新函数以启用流式输出。遇到这个提示，重新部署第 1 步的代码即可。
流式输出目前只用于话术助手，案例分析、复盘建议和文档导入仍按原来的方式等待完整结果。

直接匹配更快，是因为省去了模型生成和知识检索。流式输出让人更早看到正在生成的文字，整段回复的总生成时间仍取决于模型、输入长度和服务连接。

## 启用提问记录删除

话术助手的“我最近的提问”支持逐条删除。每条记录右侧有 **删除** 按钮，确认后会删除该条提问、保存的推荐回复和反馈，无法恢复。已保存的话术、案例和复盘内容会保留。成员只能删除自己的提问记录。

已有数据库需要更新一次删除权限。

1. 打开 Supabase 项目，进入 **SQL Editor**，新建查询。
2. 复制本目录 `ai-log-delete-setup.sql` 的全部内容，粘贴后点击 **Run**。看到执行成功即可，重复运行不会删除已有记录。
3. 刷新话术助手，找到要删除的提问，点右侧 **删除**，核对后点 **删除提问**。点 **取消** 会保留记录。

首次初始化时，最新版 `setup.sql` 已包含这项权限，无需再单独执行增量脚本。本次更新不需要重新部署 AI 函数。删除失败时记录会保留，页面会提示原因；数据库尚未更新时会提示执行上述脚本。

## 启用训练营知识库

已经初始化过的项目，只执行这个增量脚本，不必重跑 `setup.sql`。首次建库时，按第 1 步先执行基础脚本，再执行增量脚本。

1. 打开 [当前 Supabase 项目](https://supabase.com/dashboard/project/hxlsquvryfiixvjpuxfr)，进入 **SQL Editor → New query**。
2. 打开本目录的 `knowledge-setup.sql`，复制全部内容，粘贴到查询框，点击 **Run**，确认显示执行成功。
3. 按第 5 步发布更新后的前端；本地打开页面时，刷新即可。保留现有 AI 密钥与 `sales-ai` 函数。
4. 登录系统，打开顶部 **知识库**。如果仍提示未初始化，核对 SQL 是否执行在 `config.js` 指定的同一个 Supabase 项目，再刷新页面。

缺少知识库表或检索函数时，页面会提示初始化，原有话术功能仍可继续使用。只有执行增量 SQL 并完成实际保存、检索，才能确认当前环境的知识库已经可用。

### 录入资料

1. 进入 **知识库**，点击 **+ 添加资料**，填写便于查找的 **资料标题**。
2. 填写 **训练营名称**，同一训练营保持名称一致，留空表示通用资料。**资料类型**可选课程详情页、销转直播、常见问题或其他资料。
3. 选择 **适用渠道**，填写 **来源 / 有效期说明**。从原文复制内容，直接粘贴到 **资料正文**，无需上传文件，每篇最多 20 万字符。
4. **使用状态**选择启用，点击 **保存资料**。系统会保存正文并自动分块；资料过期时将状态改为停用并保存，修订后可重新启用。说明里的日期不会自动触发停用。
5. 回到知识库，在 **试试能否找到资料** 区域选好训练营和渠道，输入销售常问的问题，点击 **检索资料**，检查是否找到对应段落。

标题可以包含客户常用的说法，正文保留完整条件。长直播稿可以整篇粘贴，系统会从保存的片段中选择相关内容。

### 选择资料范围，再生成回复

话术助手需要 AI 生成时，以及案例分析和复盘建议生成时，都按训练营与渠道检索，两项条件同时生效。助手和检索测试采用页面所选渠道，案例分析沿用案例自身的渠道。
复盘页只需选择训练营，系统根据本周案例判断渠道；所有案例属于同一个具体渠道时，会检索该渠道资料，混合渠道时仅使用通用渠道资料。

| 选择项 | 会检索哪些资料 |
| --- | --- |
| 训练营留空或选择通用 | 仅通用训练营资料 |
| 选择某个训练营 | 通用资料与该训练营的资料 |
| 渠道选择不限 | 仅未限定渠道的资料 |
| 选择某个渠道 | 未限定渠道的资料与该渠道的资料 |

生成前，在 **参考哪个训练营的资料** 中选择范围，默认是 **仅通用资料**。结果中的 **本次提供的参考** 会展示本次送给 AI 的风格示例、知识片段及当时版本；点击来源可查看资料当前内容。
回复下方的 **AI 标注的资料** 对应模型在该回复中标注的来源，不表示所有检索结果都被用于回答。
给客户的消息与“销售内部提示”分开展示。资料来源、核实事项和使用说明只放在内部区，复制单条或复制全部都只复制客户正文。资料确实缺失、冲突或限定了适用范围时，正文不能作未经证实的承诺，可以自然地追问或说明需要确认；“通用资料”这个分类本身不代表政策存在疑点。

如果旧记录或新回复的正文仍混入“按通用资料”“【待核实】”等内部内容，页面会把整份方案放在内部区供检查，并提供“重新生成客户话术”。这份方案不提供复制，避免去掉核实提醒后留下不确定的承诺。原始记录会保留，重新生成时采用新的正文与内部提示规则。
从助手或复盘把 AI 草稿补进话术库时，也会检查正文。含有内部说明的草稿需要重新生成；独立填写的内部事项会保留到话术的“要点 / 禁忌”中。

这项调整只涉及前端。更新前端文件并刷新页面即可，无需执行新 SQL 或重新部署 AI 云端函数。

知识库负责提供课程事实，启用的话术库原文用来示范团队的表达方式。系统按问题挑选最多 6 条相关话术，风格示例合计不超过 7000 字；
知识检索每次最多选 6 个片段，连同来源信息控制在 6000 字符以内，不会把整库内容都发给 AI。

当前检索在服务器上按中文关键词和相邻双字组合匹配，尚未使用 embedding 语义向量检索。同义表达可能漏检，录入后可用检索测试核对，并在标题或正文中补充团队常用的问法。

## 给团队的使用说明（可以直接转发）

> 📍 https://internal.aurange.cn/sales-script/
> 第一次使用时，用 Skill 市集的账号登录；没有账号就点「注册一个」，然后让负责人在「成员」里加上你的邮箱。
>
> **平时（销售）**
>
> - **话术助手**
>   把客户的话贴进来。明确匹配到已有话术时，直接使用库内原文；要根据这次聊天改写，可以点「结合当前聊天调整」。没有明确匹配时，AI 会参考团队话术与相关知识生成，回复会逐步出现，也可以中途取消。等生成完成后，选择合适的方案逐条复制发送，不要把多个方案合成一串。用完点一下「好用 / 不好用」，不好用的会拿到复盘会上讨论。不想保留的提问，可以在「我最近的提问」中单独删除，确认后会连同这条记录的回复和反馈一起删除。
> - **提交案例**
>   每周至少交一个成交、一个流失的案例。聊天截图直接 ⌘V 粘贴，点「识别成对话」；写上关键节点和自己的复盘，再点「AI 分析」。系统会自动标出场景，并把可能用过的话术与下次建议分开列出。核对聊天后，选择当时使用的版本，点「确认实际使用」才会计入话术统计；记不清版本可以选「版本未知」。
>
> **知识库**
>
> 课程详情、销转直播内容和 FAQ 可以复制文字保存到知识库。生成回复、案例分析或复盘建议前，选好参考训练营；结果可展开查看参考快照和资料来源。课程事实用知识库补充，团队说话方式沿用启用的话术原文。
>
> **录入和发送话术**
>
> 导入或编辑话术时，一行填写一条准备独立发送的消息，页面会实时预览拆分结果。每个手动输入或粘贴保留的换行都会分出一条消息，空行会忽略；屏幕太窄造成的自动折行不会拆分消息。
>
> 话术详情和助手推荐都可以逐条复制，也可以复制全部。「复制全部」会保留消息之间的换行，粘贴后仍按实际聊天需要逐条发送。
>
> **每周复盘会**
>
> 1. 会前，打开「复盘会」，点「生成会前分析」，AI 会按场景对比成交和流失，并提出话术修改建议
> 2. 会上，点「投屏模式」，先看上周待办完成情况，再逐个过案例，把结论写进案例下面
> 3. 要改话术时，点「据此改话术」或 AI 建议的「采纳」，改动会自动记在本次复盘里，话术库升一个版本
> 4. 会后，写总结和待办，下次复盘会开头会检查
>
> 已采纳的建议可以点「重新讨论」，原话术会保留；再次采纳会编辑同一条话术。要恢复旧内容，请到话术详情中恢复历史版本。
>
> 话术库里每条话术都能看到修改记录，以及每个版本在案例里的成交情况。

## 开发与回归验证

文件分工如下。`index.html` 是页面和样式；`app.js` 负责交互；`logic.js` 是纯业务逻辑；
`workflows.js` 负责可重试导入和建议关联；`db.js` 封装数据库与演示适配器；
`ai.js` 放提示词，`ai-status.js` 记录实际服务商和连接状态；`knowledge.js` 处理知识资料、话术匹配和参考内容；
`stream.js` 读取流式事件并处理取消和旧函数响应；`reply-content.js` 识别客户正文里混入的内部说明；
`setup.sql`、`knowledge-setup.sql` 部署到 Supabase 数据库，`edge-function/sales-ai.ts` 部署为云端函数。

助手流式输出需要前端与云端函数一起更新，不涉及数据库迁移。接口采用分段返回内容的方式，具体格式见 [OpenAI 流式事件说明](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)和 [DeepSeek Chat Completions 说明](https://api-docs.deepseek.com/api/create-chat-completion/)。

本地预览时，在仓库根目录运行 `python3 -m http.server 8000`，打开
`http://127.0.0.1:8000/sales-script/?demo=1`。只有明确带 `demo=1` 才启用演示；
正式模式缺配置或数据库组件加载失败时会显示错误，不会切换成本地数据。

使用 Node.js 22.13 或更新版本运行测试，无需安装依赖。函数测试使用 Node 内置的 TypeScript 转换功能。

```bash
node --test sales-script/tests/*.test.js
```

测试只使用虚构数据和内存适配器，不连接生产、不调用付费 AI。白名单中的 `.test.js` 文件可提交；
`tests/` 中其他文件仍被忽略，避免把业务样例带进仓库。

知识库新增表和检索函数，已有项目需要执行 `knowledge-setup.sql`；原有数据继续保留。检索与风格示例由前端配合数据库提供，无需为此更新 AI 云端函数。
旧案例中的话术关联无法自动判断
哪些来自旧 AI、哪些是人工记录，因此会保留；编辑页会提示逐条核对，未使用的移除，使用过的重新确认版本。
旧待办会在保存总结时补上固定编号；没有编号的待办若遇到他人修改，会停止保存并提示重新确认最新列表。

批量导入部分失败时，已成功的条目不会重复导入，未完成条目及人工编辑保留在当前页供重试。
正式上线仍需使用真实成员账号验证登录、权限、截图识别和 AI 调用；演示测试不代表这些服务已经部署成功。
